# Free-LLM Availability Dashboard

A static [GitHub Pages](https://danissimode.github.io/litellm-free-models-prox-DNy/) site that tracks the live availability of **free-tier LLM models** across providers. It probes each provider's API directly (no proxy in between), aggregates uptime/latency, and renders the results as a static site under `docs/`.

Fork of [cheahjs/litellm-free-models-proxy](https://github.com/cheahjs/litellm-free-models-proxy), stripped down to the availability site only — the LiteLLM proxy, sync, Postgres, and compose stack have been removed.

## What this is

- **Direct provider probing** — `probe_models.py` calls each provider's chat-completions endpoint with a tiny `ping` request (max_tokens=1) and classifies the result: `ok`, `rate_limited`, `quota_exhausted`, `auth_error`, `not_found`, `server_error`, `timeout`, `bad_response`, `network_error`.
- **Uptime + latency aggregation** — rolling 7-day and 30-day uptime, p50/p95 latency, hourly uptime per model, written to `docs/availability.json`.
- **Static site generation** — `generate_site.py` turns the model + availability data into the HTML pages under `docs/`.
- **Fully automated** — GitHub Actions probes every 30 min (`probe.yml`) and rebuilds the site hourly (`update-models.yml`).

## What this is not

- **Not a proxy/gateway.** There is no LiteLLM, no compose stack, no Postgres, no API keys on a server. Everything runs as GitHub Actions + a static site.
- **Not a model registry.** The site reports availability; it does not serve inference.

## Quick start (local)

```bash
git clone https://github.com/Danissimode/litellm-free-models-prox-DNy.git
cd litellm-free-models-prox-DNy
cp .env.example .env     # optional: fill in provider keys you hold
pip install -e ".[dev]"  # pytest + ruff
```

Probe once and build the site:

```bash
python3 probe_models.py          # needs docs/models.json; appends docs/probes.jsonl, writes docs/availability.json
python3 generate_site.py         # rebuilds all pages under docs/
python3 -m http.server 8000 --directory docs   # preview locally
```

Provider keys are **optional**. Providers without a configured key are skipped (or probed anonymously where supported, e.g. `llm7`). `provider-check.sh` is a one-shot reachability check against each provider's `/models` endpoint.

## How it works

```
provider APIs ──(direct probe)──▶ probe_models.py ──▶ docs/probes.jsonl
                                                        │  (every 30 min, probe.yml)
                                                        ▼
                                              docs/availability.json
                                                        │
                                   generate_site.py ────┘  (hourly, update-models.yml)
                                                        ▼
                                              docs/  (static site → GitHub Pages)
```

- **`common.py`** — shared HTTP opener. Strips `Authorization` / `x-goog-api-key` on cross-host redirects (`SafeRedirectHandler`) — keep that behavior when touching HTTP fetching.
- **`probe_models.py`** — the probe engine. See its module docstring for the `PROVIDER_PROBES` table (env var, URL template, auth style per provider).
- **`generate_site.py`** — static site builder. **Upstream bot code: do not lint, format, or hand-edit it** (excluded in `pyproject.toml`; regenerated by `update-models.yml`).

## Required env vars

None. `.env.example` documents the optional provider keys; every key is only needed if you want that provider probed locally. The GitHub Actions workflows use their own repository secrets.

## Development / tests

```bash
python3 -m pip install --user -e ".[dev]"   # pytest, ruff
python3 -m pytest                           # dashboard invariants (offline-safe)
ruff check .                                # lint (generate_site.py excluded via pyproject)
python3 -m compileall common.py probe_models.py generate_site.py   # CI compile check
```

CI (`ci.yml`) runs: `ruff check .` → `pytest -v` → `compileall`. Run all three before pushing.

## Repository layout

| Path | Purpose |
|---|---|
| `probe_models.py` | Probe engine — hits providers, aggregates, writes `docs/probes.jsonl` + `docs/availability.json` |
| `generate_site.py` | Static site builder (bot code — don't touch) |
| `common.py` | Shared HTTP opener + free-price check helper |
| `scripts/provider-check.sh` | One-shot provider reachability check (exit 2 only on `AUTH_ERROR`) |
| `.github/workflows/probe.yml` | Probing, every 30 min |
| `.github/workflows/update-models.yml` | Site rebuild, hourly cron + on-push |
| `docs/` | Generated site — **do not hand-edit**; changes get overwritten by the hourly cron |

## Hard invariants (enforced by `tests/test_dashboard.py` — do not break)

- **No literal API keys anywhere.** Source files must not contain provider key patterns (`sk-or-v1-`, `gsk_`, `AIza`, `gh[pousr]_`, `hf_`, `nvapi-`, `sk-lf-`). Never commit a real key.
- **Every `os.environ.get(...)` read by the dashboard scripts must have a matching `KEY=` in `.env.example`.**
- **No proxy-era variables** (`LITELLM_MASTER_KEY`, `DATABASE_URL`, `POSTGRES_PASSWORD`, `SYNC_INTERVAL_HOURS`) in `.env.example`.
